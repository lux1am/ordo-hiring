# Отбор кандидатов — анкета с автоскорингом

Публичная форма на FastAPI: кандидат заполняет анкету, ответы с телеметрией
попадают в Google Sheets, дальше автоматика проверяет их и выставляет баллы
через Anthropic API. Отдельный воркер не нужен — обработка запускается
через `BackgroundTasks` того же процесса.

## Что происходит с анкетой

1. **`GET /`** — форма из `questions.json`: 6 стоп-вопросов «Да/Нет» и 5
   открытых. На каждую textarea навешена телеметрия: доля вставленных
   символов, скорость набора, количество Backspace, уходы со вкладки, общее
   время. Всё уезжает скрытым полем.
2. **`POST /submit`** — валидация, проверка на бота и дубль, запись строки в
   лист «Данные», страница «спасибо».
3. **Фоновая обработка** — идёт от номера строки:
   - любое «Нет» в стоп-вопросах → вердикт `C`, **модель не вызывается**;
   - дешёвый вызов-экстрактор достаёт из ответов числа;
   - код сверяет арифметику и конверсии, ставит флаги;
   - скорер выставляет баллы 0–3 по пяти рубрикам с обязательной цитатой;
   - вердикт пишется обратно, статус `done`.

## Раскладка таблицы

Лист **«Данные»**, шапка в строке 1, данные со строки 2. 54 колонки, A…BB.
Порядок задан в [HEADERS.py](HEADERS.py) — это единственный источник истины,
на старте приложение сверяет с ним шапку листа и жалуется в лог при
расхождении.

| Диапазон | Колонки | Что | Кто пишет |
|---|---|---|---|
| `A`–`AH` | 1–34 | id, дата, анкета, стоп-вопросы, ответы, телеметрия | `POST /submit` |
| `AI`–`AM` | 35–39 | `score_q1`…`score_q5` | обработчик |
| **`AN`** | 40 | `total_score` | **никто — формула в таблице** |
| `AO`–`AZ` | 41–52 | `ai_style` … `flags_ru` | обработчик, **частично `/submit`** |
| `BA`–`BB` | 53–54 | `manual_note`, `outcome` | **никто — заполняете вы** |

Всё пишется с `value_input_option="RAW"`. Колонка `AN` не входит ни в один
диапазон записи: там стоит `=IF(A{row}="","",SUM(AI{row}:AM{row}))`, и сумма
считается таблицей сама. Единственное место, где код использует
`USER_ENTERED` — дозапись этой же формулы начиная с 251-й строки (см. «Лимит
строк»).

### Зона `AO`–`AZ` пишется дважды

Диапазоны не образуют трёх непересекающихся сегментов, как могло бы
показаться по таблице выше. Две ячейки внутри `AO`–`AZ` заполняются уже при
сабмите:

- `AS` (`flags`) — флаги телеметрии. Считать их при обработке нельзя:
  `is_mobile` и длительность ухода со вкладки в таблицу не попадают,
  отдельных колонок под них нет, и после перезапуска процесса восстановить
  их было бы неоткуда.
- `AU` (`status`) — начальный `new`.

Обработчик перезаписывает всю зону `AO`–`AZ` целиком, поэтому **он обязан
вычитать `AS` перед записью и слить флаги телеметрии со своими** — иначе
`MOBILE` и `PASTED`, поставленные при сабмите, были бы затёрты. Это делает
`sheets.read_flags(row)` в начале обработки; поведение закреплено тестом
`test_telemetry_flags_survive_processor_write`, который гоняет полный путь
анкеты — сабмит, фоновая обработка, проверка итоговой строки.

При одном воркере (как настроено в `render.yaml`) две записи в одну зону
разнесены по времени и конфликтовать не могут: обработка стартует только
после того, как `/submit` записал строку. При нескольких воркерах это
перестало бы быть верным — см. «Ограничения».

## Подготовка Google Sheets

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте
   проект и включите **Google Sheets API**.
2. Создайте **сервисный аккаунт**, в разделе «Ключи» добавьте ключ формата
   JSON и скачайте его.
3. Откройте вашу таблицу и дайте почте сервисного аккаунта
   (`...@...iam.gserviceaccount.com`) доступ **«Редактор»**. Без этого шага
   будет ошибка 403 — сервисный аккаунт не видит таблицу автоматически.
4. Убедитесь, что шапка листа «Данные» совпадает с `HEADERS.py`, а в `AN`
   стоит формула на нужное число строк.

Содержимое файла ключа целиком кладётся в переменную
`GOOGLE_CREDENTIALS_JSON` — одной строкой, без файла на диске:

```bash
GOOGLE_CREDENTIALS_JSON=$(cat service-account.json | tr -d '\n')
```

## Локальный запуск

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # заполните ANTHROPIC_API_KEY, GOOGLE_CREDENTIALS_JSON, SHEET_ID
set -a && source .env && set +a
.venv/bin/uvicorn app.main:app --reload
```

Форма — на `http://127.0.0.1:8000/`, состояние — на `/health`.

## Деплой на Render

1. Залейте репозиторий на GitHub.
2. В Render: **New → Blueprint**, укажите репозиторий. Render прочитает
   [render.yaml](render.yaml) и создаст веб-сервис.
3. В настройках сервиса задайте три секрета (в `render.yaml` они помечены
   `sync: false`, то есть в репозиторий не попадают):
   - `ANTHROPIC_API_KEY`
   - `GOOGLE_CREDENTIALS_JSON` — весь JSON одной строкой
   - `SHEET_ID` — из адреса таблицы, часть между `/d/` и `/edit`
4. Задеплойте и откройте `/health`: там должно быть `{"status":"ok"}`.
   `misconfigured` со списком `missing_env` означает, что секрет не задан.

Логи пишутся в stdout и видны во вкладке Logs. Каждая принятая анкета
логируется целиком одной JSON-строкой **до** записи в таблицу: диск на
Render не переживает рестарт, а логи остаются, и при сбое Google API анкету
можно восстановить руками.

### Про Free-план

На бесплатном плане сервис засыпает после 15 минут без запросов, и первый
запрос после сна идёт около полминуты. Для формы это терпимо. Что важнее:
засыпание убивает фоновую обработку на полпути — от этого защищает
восстановление зависших строк, описанное ниже.

## Первый прогон

Шесть шагов после первого деплоя. Порядок важен: каждый следующий имеет
смысл, только если предыдущий прошёл.

**1. `/health` отвечает `ok`.**
Откройте `https://<ваш-сервис>.onrender.com/health`. Ответ
`{"status":"ok","missing_env":[]}` означает, что все три секрета на месте.
Если видите `misconfigured` — в поле `missing_env` перечислено, чего не
хватает; допишите в Environment и передеплойте.

**2. Шапка листа совпала с `HEADERS.py`.**
В логах Render найдите строку при старте:

```
INFO [app.sheets] шапка листа совпадает с HEADERS.py (54 колонок)
```

Если вместо неё `ШАПКА РАСХОДИТСЯ: колонка ... — ожидалось «...», в таблице
«...»` — порядок колонок разъехался, и баллы попадут не в те ячейки.
Останавливайтесь здесь и приводите шапку в соответствие. Ошибка
`APIError: 403` на этом шаге означает, что таблица не расшарена на почту
сервисного аккаунта.

**3. Обычная анкета доходит до `done`.**
Отправьте тестовую анкету, ответив «Да» на все шесть стоп-вопросов и написав
в открытые вопросы осмысленные ответы с цифрами. Проверьте строку 2:

- `A`–`AH` заполнены, `created_at` в вашем часовом поясе;
- `AI`–`AM` содержат баллы, **`AN` показывает их сумму** — если `AN` пустая,
  формула в таблице не проставлена;
- `AU` (`status`) равен `done` или `manual`;
- `AW`–`AZ` заполнены по-русски;
- `BA`–`BB` пустые.

**4. Стоп-вопрос отсекает без вызова модели.**
Отправьте вторую анкету с другим телеграмом и одним «Нет». Ожидается
`verdict=C`, `status=done`, `conditions_ru` вида «Не принял: ...», а
`AI`–`AM` пустые. В логах не должно быть ни строки про скорер или
экстрактор — это и есть подтверждение, что деньги на заведомый отказ не
потрачены.

**5. Дубль и лимит отправок работают.**
Отправьте анкету с тем же телеграмом, что в шаге 3, — должна появиться
строка со `status=duplicate` и без вызова модели. Затем отправьте шесть
анкет подряд с одного устройства: шестая должна вернуть страницу с
сообщением о превышении лимита.

**6. Эталонный прогон и калибровка.**
Локально, с боевым ключом:

```bash
.venv/bin/python tests/run_golden.py
```

Смотрите на среднюю ошибку и долю расхождений не больше 1. Если модель
систематически занижает или завышает какой-то вопрос — правьте не код, а
`rubric/qN.md`: добавьте к спорному баллу пример реального ответа. После
правки прогоняйте снова.

После шага 6 очистите тестовые строки. Следующая свободная строка считается
по длине колонки `A`, поэтому очищать нужно **с конца и вместе с колонкой
`A`**: тогда счётчик вернётся назад и строки переиспользуются. Пустая строка
в середине счётчиком не учитывается и просто останется дыркой — это не
ошибка, но и не переиспользование.

## Проверки без обращения к модели

| Флаг | Когда ставится |
|---|---|
| `PASTED` | доля вставки > 30% или скорость выше порога |
| `SUSPICIOUS` | ни одного Backspace при ответе длиннее 400 знаков |
| `TAB_SWITCH` | уход со вкладки дольше 60 секунд, после которого кандидат дописывал ответ |
| `MATH` | сделки × средний чек расходятся с выручкой больше чем на 10% |
| `OUTLIER` | конверсия из вопроса 4 выше 50% |
| `NO_NUMBERS` | экстрактор не смог достать числа |
| `MOBILE` | анкета заполнена с телефона |

**Телефоны проверяются мягче.** На мобильных `keydown` по Backspace приходит
нестабильно, а свайп-ввод и автозамена дают скорость, при которой порог для
настольных браузеров срабатывал бы почти на всех. Поэтому на мобильных
`SUSPICIOUS` отключён полностью, а порог скорости поднят с 400 до 700 зн/мин.
Событие `paste` работает везде одинаково, так что `PASTED` не смягчается.

## Баллы и вердикт

Сумма пяти баллов (0–3 каждый) даёт вердикт: **12–15 → A**, **9–11 → B**,
**0–8 → C**.

- `A` понижается до `B` при флаге `PASTED`, `MATH` или `ai_style > 70`.
- Нет подтверждённых кейсов с собственниками, CTO или ИТ-директорами
  (вопрос 3) → `C` независимо от суммы.

**Балл выше нуля живёт только при дословной цитате.** Это требование стоит
в системном промпте, но проверяется кодом: цитата ищется в тексте ответа
после нормализации (схлопывание пробелов, нижний регистр, снятие кавычек и
тире), а цитата длиннее 15 слов считается пересказом. Не прошла проверку —
балл обнуляется, причина уходит в `flags_ru`.

### Когда анкета уходит в `manual`

У ручной проверки два источника, и ведут они себя по-разному.

**Manual от экстрактора** — по вопросу 1 меньше двух месяцев с полной
тройкой чисел (сделки, выручка, средний чек одновременно), либо не
подтверждён личный результат. Скорер при этом отрабатывает нормально:
конвейер не обрывается, баллы в `AI`–`AM` пишутся, автофильтр по вопросу 3
применяется — и `C` от него переживает `manual`. Без баллов витрина осталась
бы строкой без основания для решения.

**Manual от скорера** — невалидный JSON после повтора или исчерпаны все
попытки после 429. Данных по вопросу 3 нет вообще, поэтому автофильтр не
применяется и **`C` здесь невозможен**: вердикт принудительно `B`, в
`flags_ru` уходит «оценка не выполнена, проверить вручную» плюс техническая
причина. Иначе кандидат получал бы отказ за битый JSON — то есть за чужую
вину. Закреплено тестом `test_scorer_failure_never_produces_hard_c`.

В обоих случаях колонки не остаются пустыми: `decision_ru` = «Проверить
руками», `conditions_ru` заполнен всегда.

> **Как разрешён конфликт правил.** «`manual` всегда ставит `B`» и «автофильтр
> по вопросу 3 даёт `C` независимо от суммы» противоречат друг другу.
> Развязка проходит по тому, отработал ли скорер: если да — данные по
> вопросу 3 есть, и `C` сохраняется даже при `manual`; если нет — данных нет,
> и вердикт всегда `B`. Тесты `test_hard_c_survives_manual` и
> `test_scorer_failure_never_produces_hard_c`.

## Надёжность

**Ретраи Anthropic API.** Три попытки с задержками 2/8/30 секунд, отдельно
для экстрактора и скорера. Встроенные ретраи SDK отключены (`max_retries=0`)
намеренно: иначе задержки перемножились бы и разбор волны откликов растянулся
бы на часы. В `manual` анкета уходит только после исчерпания всех попыток.

**Восстановление зависших строк.** Если процесс упал или Render
передеплоился посреди обработки, строка осталась бы в `processing` навсегда.
На старте приложения все `processing` возвращаются в `new` и ставятся в
обработку заново; дальше раз в 5 минут то же делается со строками, висящими
дольше 10 минут. Реестр захваченных строк живёт в памяти процесса, поэтому
после перезапуска все `processing` в таблице по определению осиротевшие.

**Идемпотентность.** Обработка начинается с перевода строки из `new` в
`processing` и не стартует ни при каком другом статусе. Повторная обработка
одной строки невозможна.

**Защита формы.** Скрытое стилями поле-приманка (заполнено → отвечаем
«спасибо», но в таблицу ничего не пишем, чтобы боты не съедали строки);
не больше 5 отправок с одного IP в час; повторная анкета с тем же телеграмом
пишется со статусом `duplicate` и модель не вызывает.

## Ограничения

**Один инстанс.** Номер строки выделяется так: прочитать длину колонки `A`,
записать в следующую. Внутри процесса это защищено замком, но при нескольких
воркерах или инстансах два одновременных сабмита могут получить одну строку.
Поэтому в `render.yaml` стоит `--workers 1`. Если будете включать
масштабирование, замок придётся переносить в саму таблицу — например, через
именованный диапазон-счётчик.

**`append_row` не используется намеренно.** Формула в `AN` на 300 строк
вперёд делает эти ячейки непустыми для Sheets API, и `append_row` ушёл бы
сразу за размеченный диапазон. Поэтому строка считается по колонке `A`, где
формул нет.

**Лимит строк.** Начиная с 251-й строки код сам дописывает формулу
`total_score` в `AN` — для строк 251–301 это перезапись той же формулы, а
дальше единственный способ не оставить сумму пустой. Так лимит в 300 строк
снимается сам; при выходе за размеченный диапазон в лог пишется
предупреждение.

**`notified` не заполняется.** Колонка оставлена заглушкой под уведомления,
которые добавляются отдельным шагом.

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

100 детерминированных тестов на JSON-фикстурах: раскладка колонок и зоны
записи, флаги телеметрии (включая мобильные послабления и границы порогов),
арифметика по вопросу 1, пороги и понижения вердикта, сверка цитат,
валидация формы, идемпотентность конвейера, восстановление зависших
строк, сквозной путь «сабмит → обработка». Сети не требуют.

Отдельно — эталонный прогон через реальный API с таблицей расхождений:

```bash
.venv/bin/python tests/run_golden.py                 # все фикстуры
.venv/bin/python tests/run_golden.py 01_strong_a     # выборочно
```

Он печатает по каждой фикстуре эталонный и полученный балл, среднюю ошибку,
долю расхождений не больше 1 и совпадение вердиктов. Из pytest вынесен
намеренно: это настоящие вызовы модели, то есть деньги и минуты. Запускайте
после правки промпта или рубрик.

## Настройка под себя

- **Тексты вопросов** — [questions.json](questions.json). Поля `field`
  должны совпадать с именами колонок в `HEADERS.py`.
- **Критерии оценки** — [rubric/q1.md](rubric/q1.md)…[q5.md](rubric/q5.md).
  В каждом файле оставлено место под примеры реальных ответов: добавьте по
  паре примеров к каждому баллу, и разброс оценок заметно сократится.
- **Правила скоринга** — [prompts/system.md](prompts/system.md).
- **Пороги** — переменные окружения, все перечислены в
  [.env.example](.env.example). Менять код для этого не нужно.

## Структура

```
app/main.py        FastAPI: GET / , POST /submit , GET /health
app/pipeline.py    обработка строки: стоп-вопросы → числа → баллы → вердикт
app/sheets.py      gspread: аллокация строки, три зоны записи
app/checks.py      проверки без модели — чистые функции над числами
app/extractor.py   дешёвый вызов, достающий числа из текста
app/scorer.py      скоринг, pydantic-валидация, сверка цитат
app/verdict.py     пороги, понижения, автофильтры
app/recovery.py    возврат зависших строк в обработку
app/ratelimit.py   лимит отправок с одного адреса
app/ru.py          русские тексты для витрины
app/models.py      схемы формы, телеметрии и ответов модели
app/llm.py         клиент Anthropic, разбор JSON, нормализация цитат
app/retry.py       экспоненциальный бэкофф
HEADERS.py         порядок 54 колонок — источник истины
```
