# Форма на Google Apps Script

Вариант деплоя без веб-сервера: форму отдаёт `doGet`, анкету записывает
`doPost` напрямую через `SpreadsheetApp`. Ни сервисного аккаунта, ни
`GOOGLE_CREDENTIALS_JSON`, ни Render — скрипт привязан к самой таблице и
работает от вашего имени.

## Что внутри

| Файл | Что это |
|---|---|
| `Code.gs` | `doGet`, `doPost`, валидация, флаги телеметрии, запись строки |
| `Headers.gs` | **сгенерирован** из `HEADERS.py` — порядок 54 колонок |
| `Questions.gs` | **сгенерирован** из `questions.json` — тексты вопросов |
| `Index.html` | **сгенерирован** из `templates/form.html` — CSS и JS дословно |
| `appsscript.json` | манифест: часовой пояс, доступ к веб-приложению |
| `build_gs.py` | генератор трёх файлов выше |

Три файла помечены «сгенерирован» не для красоты: порядок колонок и код
телеметрии не должны существовать в двух вариантах. Разойдясь, они начнут
писать баллы не в те ячейки и по-разному считать флаги. Правьте источники —
`HEADERS.py`, `questions.json`, `templates/form.html` — и пересобирайте:

```bash
python3 apps-script/build_gs.py
```

Тест `tests/test_apps_script.py` падает, если сгенерированное отстало от
источников или если пороги в `Code.gs` разошлись с `app/config.py`.

## Установка

**1. Откройте редактор скриптов из таблицы.**
В самой таблице: **Расширения → Apps Script**. Именно из таблицы, а не через
`script.google.com` — так скрипт получит к ней доступ автоматически, без
настройки прав.

**2. Создайте файлы и вставьте код.**
В редакторе слева, кнопка **+** рядом с «Файлы»:

| Создать | Тип | Вставить содержимое |
|---|---|---|
| `Code` | Скрипт | `apps-script/Code.gs` |
| `Headers` | Скрипт | `apps-script/Headers.gs` |
| `Questions` | Скрипт | `apps-script/Questions.gs` |
| `Index` | HTML | `apps-script/Index.html` |

Файл `Code.gs` уже существует по умолчанию — замените его содержимое
целиком. Имена файлов важны: `doGet` ищет HTML-файл именно с именем `Index`.
Расширение при создании указывать не нужно, редактор добавит его сам.

**3. Пропишите манифест.**
**Настройки проекта** (шестерёнка слева) → включите **«Показывать файл
манифеста appsscript.json»**. В появившемся файле замените содержимое на
`apps-script/appsscript.json`. Это задаёт часовой пояс и публичный доступ.

**4. Проверьте установку до деплоя.**
В выпадающем списке функций выберите **`checkSetup`** и нажмите **Выполнить**.
При первом запуске Google попросит разрешения — согласитесь (экран «Google не
проверил это приложение» → «Дополнительные настройки» → «Перейти к проекту»).

В журнале выполнения (**Ctrl+Enter**) должно быть:

```
шапка листа совпадает с HEADERS (54 колонок)
следующая свободная строка: 2
```

Если вместо этого `ШАПКА РАСХОДИТСЯ` — приведите шапку листа «Данные» в
соответствие с `HEADERS.py` и не идите дальше: иначе анкеты будут писаться
не в те колонки. Ошибка «в таблице нет листа «Данные»» означает, что лист
назван иначе — поправьте `SHEET_NAME` в начале `Code.gs`.

**5. Задеплойте как веб-приложение.**
**Развернуть → Новое развёртывание** → значок шестерёнки → тип
**Веб-приложение**. Заполните:

- **Описание** — любое, например «Анкета v1»
- **Запуск от имени** — **От моего имени** (`USER_DEPLOYING`)
- **У кого есть доступ** — **Все** (`ANYONE_ANONYMOUS`)

Оба параметра обязательны. «От моего имени» даёт скрипту право писать в
таблицу; «Все» позволяет открыть форму без входа в Google-аккаунт. Если
поставить «Все, у кого есть аккаунт Google», часть кандидатов упрётся в
страницу входа.

**6. Заберите ссылку.**
После нажатия **Развернуть** появится окно с полем **URL веб-приложения**
вида:

```
https://script.google.com/macros/s/AKfycb.../exec
```

Это и есть ссылка на форму — её отдают кандидатам. Скопируйте её кнопкой
рядом с полем.

Ссылку можно посмотреть в любой момент: **Развернуть → Управление
развёртываниями**. Она же выводится в журнал функцией `checkSetup`.

> Адрес заканчивается на `/exec` — это рабочая версия. Адрес на `/dev`,
> который иногда попадается в интерфейсе, доступен только вам и всегда
> отражает последнюю правку кода; кандидатам его давать нельзя.

## Обновление кода

После правки исходников в репозитории: пересоберите (`build_gs.py`),
перенесите изменённые файлы в редактор, затем **Развернуть → Управление
развёртываниями** → карандаш → **Версия: Новая версия** → **Развернуть**.

**Без создания новой версии правки не попадут в рабочую ссылку.**
Сохранение файла в редакторе меняет только адрес `/dev`. Ссылка `/exec`
при этом остаётся прежней — раздавать её заново не нужно.

## Чем этот вариант отличается от FastAPI

**Аллокация строки надёжнее.** `LockService.getScriptLock()` — блокировка
уровня всего проекта, а не одного процесса. В варианте с FastAPI замок живёт
в памяти воркера, и при нескольких инстансах две анкеты могли бы получить
одну строку. Здесь этой проблемы нет.

**Форма не засыпает.** Нет холодного старта, в отличие от Render Free.

**`getLastRow()` не используется.** Формула в `AN` размечена на 300 строк
вперёд, и для таблицы эти строки не пустые — `getLastRow()` вернул бы 301
сразу же. Строка считается по колонке `A`, как и в Python-варианте.

### Чего в Apps Script нет

**Лимита отправок по IP.** Адрес клиента скрипту недоступен, а
`Session.getActiveUser()` при доступе «Все» пуст. Приманка для ботов
(honeypot) и проверка дубля по телеграму работают, ограничение частоты — нет.
Если форму начнут заваливать, самая простая мера — сменить ссылку: создайте
новое развёртывание, старое архивируйте.

**Сохранения введённого при ошибке валидации.** `doPost` возвращает страницу
с описанием ошибки и ссылкой «Вернуться и исправить» (`history.back()`).
В большинстве браузеров форма восстановится из кэша, но гарантии нет.
Основную защиту даёт клиентская валидация: атрибуты `required` и `maxlength`
не дадут отправить заведомо неполную анкету.

**Квоты.** Бесплатный аккаунт: 20 000 вызовов `UrlFetch` в сутки и 90 минут
общего времени выполнения. Для анкеты это с огромным запасом — одна отправка
занимает доли секунды.

## Что дальше делает с анкетой автоматика

`doPost` пишет строку со статусом `new` и на этом останавливается. Скоринг,
проверки и вердикт остаются в Python — **их нужно запускать отдельно**,
веб-сервера с фоновыми задачами в этом варианте нет:

```bash
.venv/bin/python process_new.py
```

Скрипт подбирает все строки со статусом `new`, прогоняет их через тот же
конвейер и попутно возвращает в работу зависшие.

По расписанию он запускается из **GitHub Actions** — каждые 10 минут,
[.github/workflows/worker.yml](../.github/workflows/worker.yml). Локальный
cron для этого не нужен. Что настроить: три секрета в репозитории и почему
расписание может опаздывать — в основном [README](../README.md), раздел
«Запуск обработки: GitHub Actions».

> Обработчику нужен **свой** доступ к таблице: он приходит снаружи, из
> Actions, а не изнутри таблицы, как этот скрипт. Поэтому сервисный аккаунт
> завести придётся, даже если форма работает на Apps Script.
